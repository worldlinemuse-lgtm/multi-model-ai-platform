# Q27 — user-triggered WebGPU readiness, privacy-first resource budget

This is a **readiness and feasibility** feature only; no bundled model weights or actual local transformer inference. User explicitly initiates a read-only adapter probe in the Capabilities panel. No GPUDevice requested, no exact device limit enumeration, vendor ID, hardware information, network calls, consentless download or inference. A 96 MiB input-weight estimate is a hard conservative planning cap, not a guarantee that any browser can run such a model. Default WebGPU availability alone is not execution capability, and a valid adapter may not support model architecture or worker/CSP requirements.

Official references: W3C WebGPU spec (Privacy Considerations and requestAdapter) https://www.w3.org/TR/webgpu/ ; MDN GPU.requestAdapter https://developer.mozilla.org/en-US/docs/Web/API/GPU/requestAdapter ; MDN GPUAdapter.requestDevice https://developer.mozilla.org/en-US/docs/Web/API/GPUAdapter/requestDevice . The spec explicitly allows adapter detection failure and identifies GPU limit enumeration as a fingerprinting concern. No upstream code is copied.

Acceptance: synthetic absent/declined/successful/throwing adapter; forbid GPUDevice, downloads, inference or adapter fingerprint leakage; bounded planning-only model size; browser UI honest statuses; hosted byte integrity. Follow-up required for opt-in local model runtime, explicit model selection/download consent, license, SHA-256 model verification, device-loss handling, memory and time budgets and CPU fallback. Mark Q27 as partial until those are implemented and tested; never claim local AI inference from this probe.
