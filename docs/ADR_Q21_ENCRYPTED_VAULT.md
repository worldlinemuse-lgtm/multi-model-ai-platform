# Q21 — encrypted vault backup and passphrase rotation

2026-10-14. Preserve the existing nonextractable WebCrypto PBKDF2-SHA256 (260k iterations)→AES-GCM-256 v1 record; do not export plaintext keys or passphrases. An encrypted backup contains only the stored salt, IV, algorithm metadata and AES-GCM ciphertext. Validate each record before import; refuse overwrites unless the person explicitly confirms replacement and understands loss of the previous vault. An imported backup remains locked and requires its *original* passphrase. Passphrase rotation authenticates the old passphrase by decrypting the stored v1 record, then derives a new key using a new random 16-byte salt, encrypts with a fresh 12-byte IV and atomically writes the replacement; update the unlocked in-memory key only AFTER successful storage. No server key escrow, cross-device sync, telemetry or auto-backup.

References: MDN PBKDF2 deriveKey https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveKey ; MDN AES-GCM IV uniqueness and additionalData https://developer.mozilla.org/en-US/docs/Web/API/AesGcmParams ; MDN authenticated encryption https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt . All implementation and tests original, no copied code. Residual risk: a weak passphrase permits offline guessing against exported ciphertext; PBKDF2 strength is not a full KMS and device compromise is outside this client-side threat model.

Acceptance: wrong-pass fail-closed and byte-for-byte unchanged record, exported backup contains no plaintext test key, explicit-replace guard, proper import unlock, new-salt/new-IV rotation and post-rotation old-pass rejection, UI confirmation, hosted browser synthetic tests, no credential logs.
