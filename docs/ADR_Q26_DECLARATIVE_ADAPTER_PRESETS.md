# Q26 — data-only provider model presets

The site currently supports eight fixed, audited HTTP transport adapters. To let operators reuse preferred model/route configurations without importing arbitrary JavaScript, the extension surface is a strict, small, nonexecutable manifest: format `mm-studio-provider-presets-v1`; entries have only label, provider ID, and model ID. No endpoint URLs, headers, API keys, accounts, arbitrary scripts, or dynamic module loading. Only existing fixed provider adapters are allowed. Validation uses the same model-ID grammar as runtime requests, with OpenRouter free-only naming constraints. Up to twenty presets and 15KB import, duplicate provider/model pairs rejected. A selected preset only prefills the explicit vault connection form; it does not make HTTP requests, attest free eligibility, or overwrite encrypted credentials. The human must confirm the provider account/model and provide an eligible key as before.

Standards: IETF RFC 8259 JSON specification https://www.rfc-editor.org/rfc/rfc8259 and OWASP Third-Party JavaScript Management https://cheatsheetseries.owasp.org/cheatsheets/Third_Party_Javascript_Management_Cheat_Sheet.html motivate rejecting executable extensions; fixed trusted transport URLs are already in src/provider-api.js. No external source code copied.

Q26 is intentionally **bounded data-only extensibility**, not a working third-party plugin transport API. Full arbitrary custom providers require a separate permissions/CORS/security design and user authorization. Tests include malicious extra fields, allowed provider/model IDs, exact no-key export, browser selection without calls, offline cache SHA.
