# Q22 — Connection diagnostics and manual retry safety

2026-10-14. Provide a **network-free** local configuration check: validate provider ID, model and free-plan attestation through the existing adapter, but output only provider name, HTTPS hostname and `configured-unverified` status; never keys, account identifiers, request bodies or quota claims. The feature cannot establish provider availability, free quota, CORS access or billing eligibility. Retry assistance is a draft-only affordance: after a failed saved assistant result the user may explicitly prepare the preceding user message for a new send, but this action performs **no provider request**. The user must still click Send and may incur quota on each attempt. Do not silently retry POSTs, switch routes or replay uncertain requests.

Rationale: HTTP POST inference is not intrinsically idempotent or free; a timeout can occur after provider-side processing. User-visible retry must disclose ambiguous outcome. Network timeouts are already enforced by `callProvider` with AbortController and no automatic retry. Source: MDN Fetch API https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch ; HTTP Semantics RFC 9110 §9.2.2 https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2 ; MDN AbortController https://developer.mozilla.org/en-US/docs/Web/API/AbortController/abort . No external source code copied.

Tests: zero network attempt and no credential leak; adapter/credential invalid state; latest failed response retrieval and correct prompt; explicit two-step retry/confirm; no automatic paid fallback; existing full-site synthetic provider acceptance, hosted integrity.
